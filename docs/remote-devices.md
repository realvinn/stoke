# Other devices from the remote website

Open **Devices** in the remote website's home toolbar. The first card is the computer serving the website. Other cards show your approved Stoke devices that are online, with their shared running sessions. Pick a session to open its terminal. Back returns to Devices; choosing the current computer's sessions returns to the usual Running and Recent pages.

The computer serving the website needs this feature's Stoke update. It must be signed into your Stoke Hub account and approved in the same vault as the other computers. The other computers must have Stoke open and **Let my other devices see and open my sessions** enabled under **Accounts → Devices & sync**. They do not need their own public Phone access URL.

Opening a session uses the existing encrypted device relay. The target computer keeps its normal approval prompt and saved permissions. That prompt names the computer serving the website: the browser reaches the other computer through it. A view-only permission lets you watch; a full permission enables typing and terminal controls. Hub credentials and device keys stay on the computer serving the website.

The terminal names the target device throughout. It supports the [function keys and modifiers](remote-keyboard.md), ordinary typing, paced message submission and interruption. Fit to phone is available when the target grants control and supports remote resizing. This view opens running sessions; file transfer, starting or resuming sessions and past chat history remain on the device's own website or desktop app.

Remote drafts belong to both a device and a session. A disconnected or view-only connection keeps unsent text in the composer and never queues it for a later connection. **Try again** reconnects after a refusal or a lost relay. Leaving the page closes only that browser's relay; the target session and any desktop connection keep running.

If a device is missing, check that Stoke is running there, both computers are approved in the same vault, and the computer serving the website is connected to the Hub. A card saying sharing is off needs the sharing switch enabled on that target. Removing a device or signing out takes away its relay access.
