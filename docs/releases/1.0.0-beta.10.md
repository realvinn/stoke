Stoke 1.0.0 beta 10: clearer accounts, Notion table selection, and Grok Bot imports

This beta simplifies account navigation, makes quick terminal available by default, improves Notion and Grok Bot setup, and adds a local Codex usage-reset watcher.

- **One Accounts entry:** use Accounts at the bottom of the sidebar. The menu separates your Stoke sign-in from the account used by the current agent session. The top-right account chip is removed; usage stays at the top right. Settings → Accounts remains available when the sidebar is hidden.
- **Clearer account management:** choose an agent for its saved logins and API profiles, or Stoke for sign-in, devices and sync. New sessions labels make clear which account future launches will use. Running sessions keep their original account. Add-account forms focus the visible nickname field. Grok Bot accounts appear in this directory only while its plugin is enabled.
- **Notion table picker:** enable Work, enter the Notion integration token, then load or search tables shared with that connection. Follow additional result pages and choose separate task and daily-work tables before inspecting their properties and saving the mapping. Searching preserves selected table names. Discovery reads metadata without publishing rows or storing the draft token; saving uses the existing encrypted token store. This picker uses the Notion API. Agent MCP connections remain separate.
- **Quick terminal ready to use:** the bottom-left Terminal button opens a local shell directly, with no enable setting. The optional editable top-bar Terminal item works too. Choose an installed shell, keep commands running while hidden, or move the same shell into a separate window. Startup keeps the panel closed and starts no shell.
- **Codex usage-reset watcher:** Settings → Agents → Codex can check local terminal tabs at an editable interval, wait for the reset date/time in a usage-limit error, and send Continue or your custom message. It checks again after five hours by default and stops if Codex is running or finished normally. Typing cancels a pending watcher. The watcher is off by default, requires Stoke to remain open, and uses no paid model calls. [Watcher guide](https://github.com/realvinn/stoke/blob/v1.0.0-beta.10/docs/codex-resume.md).
- **All saved Grok Bot logins:** Read desktop sessions now distinguishes the native app's saved logins from its exported computer connections. Five saved logins remain visible when only two have recent connections. Missing or expired connections are marked and cannot be imported yet; switch to that account in Grok Bot, open Computer, reconnect and read sessions again.
- **Separate Grok Bot profiles:** Choose desktop profile folder supports instances with different data folders, including the matching Windows Local State encryption key. Refresh stays bound to the selected folder; cancelling retains the selection. Imported sessions remain encrypted and commands use the selected Stoke profile.

Grok Bot continues to use the integrity-pinned unofficial grok-bot-cli 0.12.4. Imported bot sessions do not sign in Cursor CLI or Grok Build, and native desktop control still happens through the official Grok Bot app. Cross-device account sync remains opt-in and requires approved devices in the same encrypted vault.

Downloads cover macOS Apple silicon and Intel, Windows x64 and ARM64, and Linux x64.

Setup: [Plugin and Notion guide](https://github.com/realvinn/stoke/blob/v1.0.0-beta.10/docs/plugins.md), [account sync](https://github.com/realvinn/stoke/blob/v1.0.0-beta.10/docs/account-sync.md).

Install this exact beta on macOS or Linux from a terminal outside Stoke:

```sh
curl -fsSL https://stoke.vinn.dev/install.sh | STOKE_VERSION=1.0.0-beta.10 sh
```

In Windows PowerShell:

```powershell
$env:STOKE_VERSION='1.0.0-beta.10'; irm https://stoke.vinn.dev/install.ps1 | iex
Remove-Item Env:STOKE_VERSION
```

For in-app updates, enable beta releases under Settings → Updates, then check for updates.
