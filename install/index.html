Stoke

A desktop shell for Claude Code: one window for every project, session and the browser, instead of a pile of terminals. One line installs it, and the same line upgrades it.

macOS and Linux

$ curl -fsSL https://stoke.vinn.dev | sh

Windows

> irm https://stoke.vinn.dev | iex

What it does

  • Asks GitHub for the latest release — no account, no token, nothing to sign in to.
  • Stops straight away if the version you already have is the one it would install.
  • Downloads the build for your machine from github.com/realvinn/stoke/releases and nowhere else, with a campfire to watch while it does.
  • Checks every byte against the SHA-512 in that release's own update manifest, and deletes the file and stops if it does not match.
  • On macOS, asks a running Stoke to quit properly first — killing it would strand the claude processes its sessions are running — then puts the app in /Applications and opens it.
  • On Windows, closes Stoke the same way and runs the installer silently, in the place your existing copy is already in. No administrator rights unless you already had an all-users install.
  • On Linux, puts the AppImage at ~/.local/bin/stoke with a desktop entry.

Read it first

Piping anything to a shell runs it as you. These are the exact bytes this page serves, at stable URLs, so you can read them before you run them: install.sh · install.ps1. They are the files in install/ in the repo, byte for byte.

If something between you and here rewrites your User-Agent and you get the wrong one, ?sh and ?ps1 override the guess: curl -fsSL https://stoke.vinn.dev?sh | sh.

Knobs

  • STOKE_DRY_RUN=1 — resolve, download and verify, then stop. Installs nothing.
  • NO_COLOR=1 — the fire in one colour. It still burns; NO_COLOR is about colour, not about motion.
  • STOKE_NO_ANIMATION=1 — no fire at all, one honest line per tenth instead. A pipe, TERM=dumb and CI already get this without being asked.
  • STOKE_FORCE=1 — install even when what you have is the same or newer.

Honestly

The macOS build is signed but not notarized by Apple, and the Windows installer is not signed at all. A browser download would show you a Gatekeeper or SmartScreen warning about that; curl attaches no quarantine attribute, so this route quietly does not. That is convenient and it is exactly why it is worth reading the script first.

Linux has an AppImage from the next release onwards, and no Stoke build has ever been run on Linux. Treat it as experimental — the installer says so too.
